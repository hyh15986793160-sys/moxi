# 摩西摩西 · MoXi

两个人各写一个词，同时揭晓。一样，立刻结束；不一样，你们可以自己判一句"算不算同一个意思"。

一个很小的双人同步游戏。没有账号、没有数据库，开个房间码就能玩。

---

## 玩法

1. A 点「开一局」，拿到 6 位房间码，同时得到一条邀请链接和一张二维码。
2. B 点开链接（或扫码、或手输房间码）就进了牌桌，房间里的人立刻看到对方进场。
3. 每人写下一个词，提交后锁定，**在双方都交卷之前谁也看不到对方的词**。
4. 同时揭晓：
   - 一样 → 游戏结束，撒花。
   - 不一样 → 先问一句「这两个词算同一个意思吗？」：
     - 两个人都说「算」→ 按撞上处理，游戏结束（历史里记作 `≈`，区别于字面的 `✓`）。
     - 只要有一方说「不算」→ 进入下一轮。
5. 结束后可以「再来一局」，轮次从 1 重新开始。

### 房间锁

房间只有两个座位，**坐满即锁**：

- 第三个人点邀请链接进来，会看到「这一局已经坐满了」，服务端返回 `409`，绝不会把先到的人顶掉。
- 自己刷新页面、手机切后台再回来，靠 `sessionStorage` 里的 `player_id` 回到原座位，不受影响。
- 座位 150 秒没有任何心跳才会被回收（浏览器把后台标签页的定时器压到一分钟一次，所以要给够宽限）。
  回收是"作废"而不是"让给别人"，回收后房间回到等人状态，这时新的人才能坐进来。

### 心跳与房间销毁

- 前端每 **20 秒** 打一次 `GET /api/rooms/{code}/ping`，服务端用它更新座位时间戳，并回答"你还在不在这个房间里"。
- 心跳和 900ms 的轮询是两条独立的生命线：轮询负责同步牌面，心跳只负责证明座位还有人。
  某一拍轮询卡住（比如正在提交），不会连带把座位判死。
- 页面切回前台时立刻补一次心跳，顺手把后台被节流的定时器追回来。
- 心跳返回 `404` 表示座位已经没了，前端收摊回首页。
- **房间里一个人都不剩时，房间立刻从内存里删掉**：点「离开」走 `POST /rooms/{code}/leave`，
  最后一个人走的同时房间销毁，不用等超时；如果所有人都是直接关掉浏览器，则由下一次请求顺手清扫。

### 怎么把房间发给好友

| 场景 | 做法 |
| --- | --- |
| 微信 / QQ 里发 | 点「复制邀请链接」，粘过去；链接是 `https://你的域名/moxi/?r=ABCDEF` |
| 就在对方旁边 | 让对面扫二维码，一秒进 |
| 手机浏览器 | 点「发给好友」，走系统分享面板，直接选微信 |
| 电话里念 | 6 位房间码，字符集去掉了 I/O/0/1，不会听岔 |

打开邀请链接时，前端会先问一下服务端 `GET /api/rooms/{code}/peek`：
还有空位就直接进房，省掉一次点击；房间满了（已锁）或者过期了，就停在首页说明原因。
进房之后地址栏里的 `?r=` 会被抹掉，刷新不会重复进房。

### 什么算「一样」

字面判定在服务端做，规则写死在 `backend/app/game/store.py::normalize_word`：

- 去掉首尾和中间的所有空白：`苹 果` = `苹果`
- 全角转半角：`ａｐｐｌｅ` = `apple`
- 英文不分大小写：`Apple` = `apple`
- 除此之外必须完全一致：`苹果` ≠ `苹果树` —— 这类情况交给上面的「算不算同一个」人工判定

展示时用的是你输入的原始写法，不是规范化后的结果。

## 本地开发

需要 Python 3.11+ 和 Node 20+。

**后端**（默认 8011，和 xiangq 的 8010 错开）：

```bash
cd backend
pip install -r requirements-dev.txt
python -m uvicorn app.main:app --reload --port 8011
```

**前端**（默认 6670，和 xiangq 的 6660 错开）：

```bash
cd frontend
npm install
npm run dev
```

打开 http://127.0.0.1:6670 。

**自己一个人试玩**：开两个标签页，第一个点「开一局」，第二个把邀请链接粘到地址栏，
或者直接输入房间码。身份存在 `sessionStorage`，两个标签页是两个独立玩家。

**跑测试**：

```bash
cd backend && python -m pytest -q
```

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查 |
| POST | `/api/rooms` | 开局，成为 1 号位 |
| POST | `/api/rooms/{code}/join` | 加入，成为 2 号位（满了 `409`） |
| GET | `/api/rooms/{code}/peek` | 房间概况（人数 / 是否已锁），邀请落地页用 |
| GET | `/api/rooms/{code}?player_id=` | 拉状态（轮询入口） |
| GET | `/api/rooms/{code}/ping?player_id=` | 心跳，20 秒一次 |
| POST | `/api/rooms/{code}/words` | 提交本轮的词 |
| POST | `/api/rooms/{code}/judge` | 判定 `{same: true|false}` 两个词算不算同一个 |
| POST | `/api/rooms/{code}/next` | 判定为不同后开下一轮 |
| POST | `/api/rooms/{code}/restart` | 结束后重开 |
| POST | `/api/rooms/{code}/leave` | 主动离开，腾座位；房间空了就地销毁 |

完整文档在运行时是 `/docs`。

## 部署（和 xiangq 同一台服务器）

线上是「一个域名 + 子路径」：导航页在 `/`，象棋在 `/xiangq/`，摩西摩西在 `/moxi/`。

```text
公网浏览器
    │  443
    ▼
宿主机 Nginx ─┬─ /            → /opt/sites/index.html（导航页）
              ├─ /xiangq/*    → /opt/sites/xiangq（磁盘文件）
              ├─ /xiangq/api/ → 127.0.0.1:8000（xiangq 容器）
              ├─ /moxi/*      → /opt/sites/moxi（磁盘文件）
              └─ /moxi/api/   → 127.0.0.1:8001（moxi 容器）
```

| | xiangq | moxi |
| --- | --- | --- |
| 页面地址 | `/xiangq/` | `/moxi/` |
| 接口前缀 | `/xiangq/api/` | `/moxi/api/` |
| 容器端口（宿主） | 127.0.0.1:8000 | 127.0.0.1:8001 |
| 静态目录 | /opt/sites/xiangq | /opt/sites/moxi |
| compose 项目名 | xiangq | moxi |

前端在构建时就把自己挂在子路径下（`vite.config.ts` 里 `base` 按 `command === 'build'`
切成 `/moxi/`），接口前缀来自 `.env.production` 的 `VITE_API_BASE=/moxi/api`。
开发服务器不受影响，仍然是 `http://127.0.0.1:6670/`。

打包和上线统一走仓库上一层的脚本：

```bash
cd /d/aaa/xqs
bash deploy/build.sh            # 两个前端 + 导航页 + nginx 配置，一个 tar.gz
```

完整步骤见 [`../DEPLOY.md`](../DEPLOY.md)。
只想起 moxi 容器（不含域名配置）看 `deploy/nginx/README.md` 第 1 步。

## 几个设计取舍

**为什么用轮询而不是 WebSocket。** 这是回合制，两个人的动作间隔以秒计，900ms 轮询完全够用；
而轮询走的是现成的 `/api/` 转发，Nginx 一行不用改。换成 WebSocket 就得配 `Upgrade` 头、
处理心跳和断线重连，成本远大于收益。

**为什么还要单独做心跳。** 轮询和心跳的职责不一样：轮询是"同步状态"，会被 `busy` 跳过、
会被慢请求拖住；心跳是"证明我还在"，必须简单、独立、不受业务影响。分开以后，
座位超时判断只看心跳，逻辑不会互相污染。

**为什么房间锁要牺牲"随时顶替"。** 早先的做法是"25 秒没心跳就能被别人顶掉"，
听起来宽容，实际后果是先来的人会被后来的人踹走——两个人都以为自己在这个房间里，
然后其中一个人的每一票都被 404 掉。现在改成"满了就是满了"：宁可让人重开一局，
也不让已经坐进来的人莫名其妙失去座位。

**为什么回收座位要连历史一起清掉。** 中途换人以后，新来的人没有参与过之前的轮次，
留着上一对的战绩和提交，会让他一进来就被自动结算。所以回收座位 ≈ 重新开局。

**对方没交卷时，词不会离开服务器。** 视图裁剪在 `Room.view()` 里做，未揭晓时
`opponent.word` 永远是 `null`。前端拿不到，也就没有「打开控制台偷看对方写了什么」这条路。
测试 `test_opponent_word_hidden_until_both_submit` 专门守着这条线。

**判定阶段也做裁剪。** 你还没表态的时候，看不到对方选了"算"还是"不算"，
免得被对方的选择带着走。

## 已知限制

- 没有超时机制：对方一直不交卷的话，这一轮会一直等下去（座位不会被判死，因为他在轮询）。
- 没有旁观、没有 3 人以上、没有历史存档。
- 服务重启会清空所有房间（内存存储的代价）。
- 房间 6 小时无人访问会被回收；人走光则立刻销毁。
- 邀请链接按浏览器地址栏的域名生成。本地开发时它指向 `127.0.0.1`，只在自己机器上有效；
  发给朋友必须用部署后的正式域名。
- 昵称、登录、战绩持久化都还没有（见 [`../HANDOFF-xiangq-auth.md`](../HANDOFF-xiangq-auth.md) 的规划）。
